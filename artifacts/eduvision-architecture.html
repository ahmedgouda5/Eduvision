01 · System architecture

One Express process, two backing services

Traffic enters a single API container, crosses a fixed middleware chain, fans out through seven routers, and reaches PostgreSQL through Drizzle. Redis is only used to cache the course catalog.

    05 · Authentication

    A 30-day JWT inside a 7-day cookie

    Login signs an HS256 token carrying only id and role, then places it in an httpOnly cookie. The token lifetime exceeds the cookie lifetime, and logout only clears the browser copy.

    Happy path
    POST /api/auth/login

    Credentials become a cookie

    The service compares the submitted password with the stored bcrypt hash, signs a JWT, and returns it in a strict httpOnly cookie.

      Token facts Cookie ≠ session
      header HS256
      payload { id, role }
      signature JWT_SECRET
      • AlgorithmHS256
      • Token expiry30 days
      • Cookie maxAge7 days
      • httpOnlytrue
      • sameSitestrict
      • securenot set
      • Revocationnone
      • Password hashbcrypt · 12

      A copied or already-issued token stays valid until its own 30-day expiry even after logout. Add a denylist or short-lived access token if revocation matters.

        08 · Reality check

        Where implementation trails the README

        These are code-derived gaps, not requests for changes. Each card names the evidence and the practical effect.

        High

        Enrollment path is inert

        enrollments.router.ts and its controller are empty; the router is never mounted. The service only echoes a message, so students can never actually enroll.

        src/modules/enrollments · server.ts
        High

        No content access control

        Course, lesson, quiz, question, and option reads require only a valid cookie. There is no check that the student is enrolled in the course being read.

        course/lesson/quiz routers · authenticate only
        Medium

        Catalog cache never invalidates

        allCourses is written with a 600-second TTL. Create, update, and delete operations never clear it, so fresh mutations can be hidden for up to ten minutes.

        CourseService · cache.service.ts
        Medium

        Logout does not revoke

        Clearing the cookie removes the browser copy. The signed JWT remains valid for its full 30-day lifetime if it was captured elsewhere.

        AuthService.logout · token.ts
        Medium

        Student profile patch is unscoped

        PATCH /api/auth/:id is restricted to the student role but uses the path id rather than the caller's id, letting one student target another record.

        auth.router.ts · AuthService
        Medium

        Wildcard CORS with credentials

        The app sets origin: "*" and credentials: true. Browsers reject that combination, and a broad origin policy is risky for cookie auth.

        server.ts
        Low

        Email is dead code

        Nodemailer appears in dependencies and stale dist/ output but is not imported anywhere in current source. There are no SMTP settings to configure.

        package.json · dist/ · no src/
        Low

        Video is a missing primitive

        The product promises video courses, but the data model cannot identify or authorize a video asset. Delivery would require a schema and infrastructure addition.

        db/schema/lessons.ts
        Low

        No production operations layer

        No migrations history, health endpoint, structured logger, tests, CI, or graceful shutdown were found. The server calls listen and exports nothing for testing.

        repository root · server.ts
        Bottom line

        A coherent CRUD-and-quiz API with working authentication and a sensible modular shape, but not yet a complete course business: enrollment, payments, certificates, and video delivery are unfinished.
